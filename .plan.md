# PPMaker — Feature Plan: Integração com Anthropic PPTX Skill

## Type: FEATURE ADDITION (Infraestrutura de Geração PPTX)

---

## O que estamos adicionando

Incorporação das melhores práticas da [Anthropic PPTX Skill](https://github.com/anthropics/skills/tree/main/skills/pptx) ao ppmaker, introduzindo:

- **Scripts unpack/pack** para edição direta de XML do PPTX (mais confiável que clonagem via python-pptx)
- **Terceiro caminho de renderização**: unpack → editar XML slide por slide → pack
- **Pipeline de QA visual**: geração de thumbnails para inspeção e verificação de qualidade
- **Skill de Claude Code** (`SKILL.md`) que codifica o fluxo de construção de PPTs no projeto

**Novo fluxo de prioridade de renderização:**
```
1. XML-based (unpack → edit XML → pack)   ← NOVO (melhor qualidade, template fidelidade máxima)
2. Stencil-based (clone slides via python-pptx)  ← atual preferido
3. Programmatic (draw shapes from scratch)        ← fallback
```

---

## Por que esta feature

A abordagem da Anthropic skill edita diretamente o XML interno do PPTX, o que:
- **Preserva 100% da formatação original** — fontes, animações, SmartArt, estilos, tudo
- **Permite edição paralela** — cada slide é um arquivo XML separado (subagentes podem trabalhar em paralelo)
- **Não corre risco de corrupção** — python-pptx pode corromper namespaces ao clonar slides complexos
- **Suporta QA visual integrado** — thumbnails gerados por LibreOffice permitem verificação antes de entregar o arquivo

A abordagem atual (StencilRenderer) tem limitações conhecidas com templates complexos (AnimatedSmartArt, efeitos avançados, SmartArt) e não tem nenhum passo de verificação visual.

### 2. Novo serviço: `backend/services/xml_renderer.py`

Novo caminho de renderização que usa unpack → edit XML → pack:

**Fluxo interno:**
1. Copia o template PPTX para um diretório temporário
2. Chama `unpack.py` para extrair e formatar o XML
3. Para cada slide do outline: seleciona o slide-modelo correto do catálogo via VisualDirector
4. Usa `add_slide.py` para duplicar o slide-modelo
5. Edita o XML do slide clonado (título, bullets, placeholders)
6. Chama `clean.py` para remover arquivos órfãos
7. Chama `pack.py` para gerar o PPTX final
8. Retorna `io.BytesIO`

**Regras de edição XML (baseadas em Anthropic editing.md):**
- Usar `<a:r>` separados para cada parágrafo, nunca concatenar em string
- Usar `b="1"` em headers/títulos
- Nunca usar bullets unicode `•` — usar `<a:buChar>` ou `<a:buNone>`
- Smart quotes como entidades XML: `&#x201C;` / `&#x201D;`
- Usar `defusedxml.minidom` para parse (nunca `xml.etree.ElementTree`)

### 3. Atualizar `backend/services/pptx_service.py`

Adicionar o XML renderer como primeira opção de renderização:

```python
# Nova ordem de prioridade:
def generate_pptx(outline, template_path, template_meta):
    # 1. XML-based (novo, melhor qualidade)
    if xml_renderer_available():
        try:
            return _generate_pptx_xml(outline, template_path, template_meta)
        except Exception as exc:
            logger.warning("XML renderer failed (%s). Trying stencil.", exc)

    # 2. Stencil-based (atual preferido)
    stencil_path = _find_stencil_file(template_path)
    if stencil_path and catalog_available():
        try:
            return _generate_pptx_stencil(outline, stencil_path, catalog_path, template_meta)
        except Exception as exc:
            logger.warning("Stencil failed (%s). Falling back to programmatic.", exc)

    # 3. Programmatic (fallback)
    return _generate_pptx_programmatic(outline, template_path, template_meta)
```

**Flag de controle via `.env`:**
```
PPTX_RENDERER=xml|stencil|programmatic|auto   # default: auto
```

```markdown
# PPMaker — Skill de Geração PPTX

## Quando ativar
Qualquer menção a slides, apresentações, deck, PPTX, PowerPoint — seja criação, edição, análise ou manutenção.

## Abordagem preferida: XML-based (unpack → edit → pack)

### Para criar uma apresentação nova a partir de um template:
1. Analisar o template: python scripts/thumbnail.py template.pptx
2. Extrair conteúdo do template: python -m markitdown template.pptx
3. Desempacotar: python scripts/office/unpack.py template.pptx unpacked/
4. Planejar mapeamento de slides (conteúdo → layout)
5. Fazer TODAS as mudanças estruturais (adicionar/remover/reordenar slides) ANTES de editar conteúdo
6. Editar conteúdo XML de cada slide (usar EditTool, não sed/python)
7. Limpar: python scripts/clean.py unpacked/
8. Empacotar: python scripts/office/pack.py unpacked/ output.pptx --original template.pptx
9. QA visual: usar LibreOffice + pdftoppm para inspecionar slides gerados

### Regras de edição XML
[Regras do editing.md da Anthropic skill]

### QA loop obrigatório
1. Gerar PPTX
2. Converter para imagens (LibreOffice → PDF → imagens)
3. Inspecionar todos os slides
4. Documentar problemas
5. Corrigir e reverificar
6. Repetir até zero problemas novos
```

## Riscos e mitigações

| Risco | Impacto | Prob | Mitigação |
|-------|---------|------|-----------|
| LibreOffice ausente no ambiente de prod | M | M | Degradação graciosa: thumbnail endpoint retorna 503; pipeline não bloqueia |
| XML editing corrompe o PPTX (smart quotes, namespaces) | A | M | Usar `defusedxml.minidom`; pack.py valida antes de salvar; testes com PPTX real |
| Arquivo temporário não limpo (crash no meio da geração) | M | B | Usar `tempfile.TemporaryDirectory()` como context manager — garante cleanup |
| Template Ambev bloqueado pelo OneDrive durante unpack | M | A | Já tratado no `render_from_template.py` — porta o mesmo padrão (cópia para TEMP) |
| Scripts Anthropic dependem de Python 3.10+ | B | B | Checar compatibilidade; ppmaker já usa 3.11 |
