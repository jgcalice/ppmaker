# PPMaker Test Strategy

## Overview

Risk-based testing strategy for PPMaker — a web app (Next.js + FastAPI) that transforms plain text into professional PowerPoint presentations using AI.

## Test Pyramid (Testing Trophy)

```
         ┌─────────┐
         │   E2E   │  ← Happy paths only (slow, fragile)
        ┌┴─────────┴┐
        │ Integration│  ← API contracts, service interactions
       ┌┴───────────┴┐
       │    Unit     │  ← Business logic, validation, edge cases
      ┌┴─────────────┴┐
      │  Static/Types │  ← Pydantic schemas, TypeScript
      └───────────────┘
```

## Risk Classification

### Critical (E2E + Integration + Unit)

| Flow | Risk | Mitigation |
|------|------|------------|
| Text -> storytelling outline -> PPTX download | Core value proposition; any failure = zero value delivered | Happy-path E2E, API integration tests, unit tests for each service |
| PPTX generation produces valid file | Invalid PPTX = user gets corrupted download | Unit test: open generated bytes with python-pptx |
| Template selection + loading | Wrong template = wrong branding | Integration: filesystem scan, metadata validation |

### High (Integration + Unit)

| Area | Risk | Mitigation |
|------|------|------------|
| `pptx_service.generate_pptx` | Slide count mismatch, missing placeholders, wrong titles | Unit tests with sample outline |
| `template_service` filesystem scan | Missing dirs, corrupt JSON, scope filtering | Unit tests with temp directories |
| Input validation (content length, path traversal) | Security: injection, DoS via oversized content | Unit tests for boundary values |
| API schema contracts | Breaking changes between frontend and backend | Contract validation tests |

### Medium (Unit)

| Area | Risk | Mitigation |
|------|------|------------|
| Pydantic schema validation | Schema drift | Schema unit tests |
| SSE event structure | Frontend can't parse events | Contract tests |
| AI prompt structure | Not directly testable without API key | Validate _parse_outline with sample responses |

### Low (Manual / Deferred)

| Area | Risk | Mitigation |
|------|------|------------|
| Visual fidelity of PPTX | Colors, fonts, layout positioning | Manual review |
| Color accuracy in palette | Hex conversion edge cases | Unit test for `_hex_to_rgb` |
| Responsive frontend layout | CSS/layout issues | Manual + future visual regression |

## Test Categories

### Backend Unit Tests (`backend/tests/`)

- **test_template_service.py** — filesystem scanning, metadata parsing, error handling
- **test_pptx_service.py** — PPTX generation, slide count, titles, placeholders
- **test_security_service.py** — input validation, path traversal prevention
- **test_api_schemas.py** — FastAPI endpoint responses, status codes, validation
- **test_contracts.py** — response shapes match documented API contracts

### E2E Tests (`e2e/tests/`)

- **happy-path.spec.ts** — full flow: template selection -> content input -> storytelling -> PPTX download
- **error-states.spec.ts** — content too long, loading states, template gallery

## Test Data Strategy

- **Sample outline fixture** (`conftest.py:SAMPLE_OUTLINE`) — 3 slides covering title, content, and chart-placeholder layouts
- **Temp template directory** (`conftest.py:temp_template_dir`) — isolated filesystem with valid JSON metadata
- **No real AI calls in unit tests** — mock `_call_claude` or test `_parse_outline` with canned responses

## CI Integration Guidelines

- Backend: `cd backend && pytest tests/ -v --tb=short`
- E2E: `cd e2e && npx playwright test` (requires both frontend and backend running)
- Target: all unit/integration tests run in < 2 minutes
- E2E tests run only on merge to main (slower, needs full stack)
